# Nexstar, TEGNA and Scripps adapter fixtures

Every file here is a real response body, live or archived.

Live bodies were read once from the station's server (or the file its closings
page frames) with the pipeline's own client,
`snowlight.sources.stations.http.PoliteClient`, as `group_fixtures capture` does:
the repository's User-Agent, robots.txt read first and its verdict recorded (none
of these URLs was disallowed), per-host pacing. A live body cannot be downloaded
again as it was: its SHA-256 is the one the capture log recorded when it was read.

Archived bodies are Wayback Machine `id_` captures (the bytes the station served
when the archive read the page), downloaded on GitHub's runners by
`.github/workflows/archive-captures.yml` and added with `group_fixtures
add-archived`. `Captured` is when the archive read the page (the capture the
archive served, which may be near rather than at the one asked for) and
`Retrieved` when the runner downloaded it. The original SHA-256 is of the bytes
as the archive sent them (a page the station served gzip-encoded is still gzip):
download the capture link without decoding it, confirm the SHA-256, slice it, and
compare bytes.

The stations' terms forbid reading their sites with software; they are recorded
in `pipeline/config/sources/` with the project owner's decision (2026-09-25) to
read the closings lists anyway.

Bodies are cut with the method named below
(`snowlight.sources.stations.group_fixtures.SLICERS`): a page keeps only its
closings module (or the frame naming its list file), a WordPress REST page keeps
its id, link, slug and modification time and, of its content, the closings article
(or the list frame), and small files are kept whole. A page typed by hand (`-v3`)
keeps the tags that give its title and time and its typed block; a REST page typed
by hand keeps its title and whole content. Slicing a slice changes
nothing, and a slice reads exactly as its original did. Full SHA-256 values and
the exact names the adapter reads are in `PROVENANCE.json`.

This file is generated from the provenance files; edit those, not this.
